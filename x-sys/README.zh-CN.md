# Open-X-Sys：这个家族

[English](README.md)

**Open-X-Sys** 是建立在 OpenXSys 内核之上的领域系统，命名为 **Open{领域}Sys**。

**现状。** 这个文件夹里放的是约定。还没有任何 X-Sys 发布。计划中的首批两个是 **OpenCreatorSys**（最能展示实践、依赖与媒介）和 **OpenLearnSys**（展示一个人的成长）；随后是 OpenResearchSys、OpenCodeSys、OpenTeamSys 和 OpenCitySys。

## 一个 X-Sys 增加什么，继承什么

| 它为自己的领域增加 | 它原样继承 |
|---|---|
| 领域方法及其问法 | 七阶段的旅程 |
| 领域路线与高手路线，附来源 | 23 个方法、7 个视角和模式库 |
| 研究过的实践，附条件与证据 | 四种使用方式、路线条、学习模式 |
| 审查过并锁定的依赖 | 系统的组成部分与 `SYSTEM.md` 约定 |
| 高风险领域自己的不变量 | 两份认识记录 |
| 给试验场的现成对象 | 最佳实践研究、全力开启及其护栏 |
| | 签名、分享包、信任规则、五条不变量 |

X-Sys 从不削弱它继承的东西。它可以更严格：一个健康或法律领域的 X-Sys 会增加不变量，而不是去掉任何一条。

## 怎样造一个

X-Sys 本身是一个 Agent Skill，用自然语言写成，并写明 OpenXSys 是它的内核。

```text
skills/open-<领域>-sys/
├── SKILL.md            这个领域系统为了什么；它增加了什么；什么时候交回给内核
├── methods/            领域方法，每个一页，用内核方法页的样子
├── routes/             领域路线与高手路线
├── practices/          研究过的实践，附条件与证据
├── deps/               它自己的锁定文件（如果它内置了任何东西）
└── playground/         这个领域的现成对象
```

- 它的 `SKILL.md` 在开头几行就写明：OpenXSys 内核完整适用，这里只列出它增加的东西。
- 每个增加的方法都有来源、有真实运行，页面写“是什么”和“为什么”，从不写步骤。
- 每个增加的依赖，都按运行时里 `kit/KIT.md` 的要求审查并锁定。
- 先写英文，再写结构完全一致的完整中文版。

## 兼容性测试

当一个同时安装了内核和这个 X-Sys 的全新 agent，仍然通过内核的验收测试（公开验证说明 docs/VALIDATION.zh-CN.md，记录在 `evals/`），并且额外满足下面几条时，这个 X-Sys 算是兼容的：

1. 领域之内的请求，用领域的方法来回答，并且仍然带着完整的签名。
2. 领域之外的请求，由内核处理，就像这个 X-Sys 不存在一样。
3. 护栏和五条不变量，在每条领域路线里都成立。
4. 条件不同的两个人，得到不同的实践。
5. 留下的系统，交给一个只有内核的 AI，仍然通过接续检验。

## 系统集市

系统集市是兼容的 X-Sys 的索引。它从下面这张表开始。

| X-Sys | 领域 | 维护者 | 状态 |
|---|---|---|---|
| OpenCreatorSys | 制作与发布内容 | | 计划中 |
| OpenLearnSys | 学习一个学科或一项技能 | | 计划中 |

要被收录，一个 X-Sys 需要通过兼容性测试，并且它的依赖有带日期的审查记录。

## 系统公地

人们可以发布自己开启的某个系统、自己验证过的某项实践，或自己搭的某条路线，让别人打开、适配、分叉。个人的根系统永不分享。分享会先去掉一切个人内容，并完整展示将要公开的东西（运行时里的 `system/consent.md`）。分享出去的实践带着它的条件与证据，分叉保留一行谱系。公地会随着第一批真实分享的系统开放；现在还没有。
