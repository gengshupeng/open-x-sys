# Open-X-Sys：让每个人创造自己的 Sys

[English](OPEN-X-SYS-DRAFT.md)

> **设计草稿。** OpenXSys 已经建立递归自然语言运行时、可运行的系统实例、关系与能力模型、用户拥有的连续系统，以及连接 AI 工具与外部系统的适配层。这份草稿继续定义：任何人怎样在这套共同地基上创造、拥有、连接和演化自己的 Sys。

## 一句话

**OpenXSys 打开共同地基，让每个人都能基于它，为自己关心的事物创造、拥有和发展自己的 Sys。**

```text
OpenXSys + 你的目的、认识、方法、工具与现实
                         ↓
                    你的 Sys
```

这里的 `X` 是一个向所有人开放的位置。它可以是一项工作、一个项目、一门学科、一个行业、一种创作、一个社区，也可以是尚未被命名的新事物。

## 名字里的三个部分

| 部分 | 含义 |
| --- | --- |
| **Open** | 人们可以理解、拥有、改造、连接、分享和分叉自己的系统。开放首先是创造权，不只是查看源码。 |
| **X** | 任何人、对象、领域、能力或共同目标都可以进入这里。X 不由 OpenXSys 项目预先填满。 |
| **Sys** | 它不是一段提示词或一次回答，而是能够认识对象、组织能力、产生作品、接受反馈并继续演化的系统。 |

因此，Open-X-Sys 是一种开放的系统生成方式。OpenCreatorSys、OpenLearnSys、OpenResearchSys 或 OpenCitySys 可以成为项目和社区创造的例子；真正重要的是，任何人都能建立适合自己的 Sys，也可以使用自己的名字。

## 谁可以创造什么

- **个人 Sys**：把一个人的学习、创作、研究、工作或生活作为能持续生长的系统。
- **项目 Sys**：让项目的目的、认识、能力、作品、关系和接力点共同运行。
- **领域 Sys**：把一个领域真正有效的方法、知识、工具、数据和实践组织成 AI 可以使用的系统。
- **团队与社区 Sys**：让多人拥有的系统围绕共同目标协作，同时保留各自的权利和边界。
- **公共 Sys**：把值得共享的认识、能力和作品开放出来，让别人采用、验证、适配和继续发展。

一个 Sys 可以只属于创造者，也可以公开；可以独立运行，也可以和其他 Sys 组成更高层系统。私有或公开，始终由它的创造者和所有者决定。

## 从 OpenXSys 的共同地基上生长

一个 Sys 从 OpenXSys 获得共同地基：

- 用系统理解系统，用系统建造系统；
- 人只需自然表达，AI 主动承担复杂性；
- 过程保持自由，判断建立在系统科学、证据和真实反馈上；
- 认识要抵达人，最终形成作品、选择、行动或新能力；
- 系统属于它真实的所有者，能够被阅读、纠正、带走和结束；
- 成长以未来行为是否改变来衡量。

它再从自己的世界里长出独特部分：

| Sys 自己拥有 | 可能包含什么 |
| --- | --- |
| **目的与对象** | 它为谁存在，要改变什么，怎样的结果真正有价值。 |
| **领域认识** | 关键概念、对象模型、证据、未知、争议和变化。 |
| **方法与实践** | 这个领域有效的问法、判断、路线、条件和经验。 |
| **能力与工具** | 模型、Skill、代码、数据、设备、人员以及它们的连接。 |
| **作品与体验** | 这个系统最适合创造的成果，以及人怎样理解和使用它们。 |
| **边界与权利** | 权威状态、权限、风险、责任、纠正和退出方式。 |
| **反馈与演化** | 怎样知道它真的有效，什么时候更新、分化、合并或淘汰。 |

共同地基保证这些系统能够彼此理解和连接；独特部分保证它们不会长成同一种模板。

## 自然语言应该成为创造入口

未来，创造 Sys 不应从填写框架或复制目录开始，而应从一句真实的话开始：

> 为我的独立研究工作建立一个 Sys。

> 把我们团队已经验证的产品方法做成一个可以共同使用的 Sys。

> 我想为这座城市的步行体验创造一个开放系统。

AI 先帮助创造者理解对象、目的、边界和已有条件，再把真正需要的认识、能力、工具、作品与反馈组织起来。文件结构和机器索引由系统按需生成；人始终可以用自然语言理解、修改和继续它。

## 一个开放生态怎样生长

```text
一个人创造自己的 Sys
          ↓
在真实工作中运行、验证和演化
          ↓
选择保持私有，或公开可分享的部分
          ↓
别人采用、适配、连接或分叉
          ↓
形成新的 Sys 与更高层系统
          ↓
真实结果回到原系统与公共认识
```

这条路径可能逐渐长出两个公共空间：

- **Sys Hub**：发现和理解公开 Sys 的入口。它帮助人判断一个 Sys 为了什么、适合什么条件、依赖什么、由谁维护，并不垄断创造权。
- **Systems Commons**：人们共同分享系统、方法、实践、能力和作品的开放公地。分享保留来源、条件、版本和演化谱系，让后来者能够真正接续。

一个开放生态的价值，不在于收录了多少名字，而在于人们是否能创造原本不存在的能力，并让这些能力在不同系统之间继续生长。

## 与当前版本的关系

`0.1.0-alpha.1` 的主线仍然是让 OpenXSys 作为一个系统级 Skill，在用户正在使用的 AI 工具中完整工作：看得透，想得清，做得成，连得上，会生长，越用越强。

当前架构已经为 Open-X-Sys 留下地基：可运行的系统实例、自然语言入口、用户所有权、关系、能力、适配器、语义索引、组成与演化。当前工作先让这些基础在更多真实对象和 AI 工具中经受检验。Open-X-Sys 的正式继承方式、互操作约定、发现机制与公共生态，将从真实创造出来的 Sys 中继续推导。

因此，这份草稿现在承担三件事：

1. 让 OpenXSys 的开放方向不再从项目叙事中消失；
2. 给想创造自己 Sys 的人一个可以讨论和试验的共同起点；
3. 让未来设计能够建立在本版已经验证的运行基础上。

## 进入正式设计前要回答的问题

- 一个 Sys 最少共享哪些语义，才能仍然保持自己的自由形态？
- OpenXSys 与一个 Sys 之间是继承、组成、连接，还是几种关系同时存在？
- AI 怎样从普通表达中发现、选择、组合或帮助创造合适的 Sys？
- 多个 Sys 同时作用时，怎样处理目的、方法、权限和权威状态的冲突？
- 怎样表达版本、来源、依赖、适用条件、验证记录和分叉谱系？
- 怎样让互操作成为真实作用，而不是文件格式相同或图上多一条连线？
- Sys Hub 与 Systems Commons 怎样保持开放，同时让人能够判断质量、风险和维护状态？

这些问题将通过架构讨论、真实作品和实际创建的 Sys 一起回答，让正式约定从开放生态真正需要的关系中自然长出来。
