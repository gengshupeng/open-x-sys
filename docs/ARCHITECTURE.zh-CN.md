# OpenXSys 的本质与自然语言系统架构

[English](ARCHITECTURE.md)

**主角都有系统。现在，你也有了。**

OpenXSys 是一个运行在 AI 工具和电脑环境中的**递归自然语言开放系统运行时**。人只需说出已经想到的部分，AI 在背后理解系统、组织或创造能力、作用现实并吸收反馈。用户拿到的是改变认识的发现、真正完成的作品和以后仍能使用的新能力。

它不要求人学习建模、填写状态或操作工作流。内部越严谨，前台越应该简单、自由、有生命。

[完整 Skill](../skills/open-x-sys.zh-CN/SKILL.md) · [Open-X-Sys 设计草稿](OPEN-X-SYS-DRAFT.zh-CN.md) · [安装](INSTALL.zh-CN.md)

## 从一句普通的话开始

用户可以只说：

> 我想研究一下人工智能这整个产业。

他不需要先知道产业应该怎样划分，不需要选择研究方法，也不需要设计输出格式。OpenXSys 先接住这句话，恢复已有系统和材料，主动找到真正值得追的结构，再把认识做成对象最适合的作品。

一次完整体验通常让四种事情真实发生：

- **惊喜**：看见过去看不见的关系或成品。
- **自由**：随时追问、纠正、换方向、参与和接手。
- **获得**：带走能理解、能使用、能继续创造的东西。
- **成长**：这次获得改变下一次运行。

用户默认不会看到内部的系统元模型、关系语义、运行回路和依赖传播。只有打开全景、依据或设计时，它们才以可理解的形式展开。

## 两张同时成立的结构图

### 物理包含关系

```text
电脑系统
├── 硬件、操作系统、文件、进程和网络
├── AI 宿主
│   ├── 会话、上下文与事件
│   ├── LLM
│   ├── 工具、权限与执行
│   └── 状态回传
├── OpenXSys 自然语言运行时
└── 用户拥有的系统、作品、数据和工具
```

人通过设备与 AI 工具进入。远程模型、软件、组织和设备通过文件、网络、接口或人的行动发生联系。

### 实际作用关系

```text
人、AI、电脑、现实对象、项目系统和其他独立系统
       ↕ 观察、意义、行动、权限、结果与反馈
             OpenXSys 当前活动系统
```

物理上存在嵌套，作用上形成网络。一个模型可以在另一台电脑运行，一个人也可能是研究对象，一个现实系统始终按自己的机制运转。OpenXSys 组织的是这些系统之间能够产生实际作用的关系。

## 真正的中心：可运行的系统实例

每次运行都围绕一个当前活动系统，而不是围绕某条提示词、某个方法或一轮对话。

它可以是公司、行业、城市、项目、代码库、一个人的工作，也可以是一项能力、一条关系，或几个独立系统临时组成的更高层系统。

一个系统至少具有以下语义。它们是 AI 必须能理解的问题，不是用户填写的字段。

| 方面 | 要弄清什么 |
| --- | --- |
| **身份与目的** | 它是什么，为谁服务，当前什么结果有价值。 |
| **边界与尺度** | 这次看哪里、看到哪一层、跨多长时间。 |
| **现实、观察与模型** | 对象实际怎样，当前看见什么，我们推断什么，还有什么未知。 |
| **组成与关系** | 哪些部件参与，真正传递作用的关系是什么。 |
| **约束与资源** | 什么限制整体，哪些条件可以改变，约束会不会移动。 |
| **能力** | 已经能做什么，哪些经过验证，目标还缺什么。 |
| **所有权与权限** | 状态、资料、作品、决定和执行分别归谁。 |
| **作品与行动** | 认识怎样抵达人，意图怎样进入现实。 |
| **反馈与演化** | 什么会改模型、能力、关系、边界或目标。 |

本轮运行形成活动图景，长期有价值的部分由 `SYSTEM.md`、作品、代码、数据和连接承载。临时推理、工具日志和未经检验的猜测不会因为“发生过”就成为系统状态。

## 系统是递归的

OpenXSys 中不存在永远只能当部件的东西。

- 一个组件内部决定结果时，可以展开成系统。
- 一条关系包含观察、转换、权限和反馈时，本身就是关系系统。
- 一项能力拥有状态、边界和演化后，可以成为独立系统。
- 一件作品被反复使用并能反馈效果时，可以成长为能力。
- 多个系统围绕共同目的形成实际作用时，可以组成更高层系统。

弄清局部之后必须回到整体，检查它怎样改变上层目的。换尺度不是为了画更多层，而是为了找到反复生成当前现象的结构。

> **高一层的结构，会在低一层表现为反复发生的问题。**

## 关系：最小的活结构

系统不是由节点构成，而是由能够产生作用的关系构成。重要关系必须能够说明：

```text
谁 → 作用于谁
传递什么
接收方怎样理解或转换
什么条件下有效
状态与决定权归谁
作用需要多久
预期改变什么
怎样确认受理、执行、状态与效果
失败后返回哪里
怎样暂停、替换、撤回或退出
```

**鸿沟**不是图上没有连线，而是一个系统拥有的差异、认识或能力，无法在另一个系统里形成可用作用。

解决鸿沟时，OpenXSys 判断缺的是观察、翻译、行动、协调还是反馈，再组织一套桥接系统。它可以由人、AI、自然语言约定、现成工具、生成代码、共同数据和新的分工组成。桥接系统本身也可以被检验和演化。

## 能力：经过现实验证的关系结构

模型、数据和工具放在一起，不自动成为能力。能力是在适用条件下，多个部分能够重复把某种输入或状态变成有价值结果，并能观察效果、发现失效和重新组织。

```text
目标要求
  ↓
发现当前系统够不到的能力鸿沟
  ↓
复用、适配、组合或创造实现
  ↓
用样本、反例、权限和真实工作检验
  ↓
接入系统并留下适用条件
  ↓
以后复用、重验、替换或继续演化
```

生成一段代码只是候选实现。隔离测试通过是已测试实现。只有在用户真实工作中完成任务并得到相应确认，才能称为已验证能力。

## 运行：三个回路自由组织

OpenXSys 不规定一条用户流程。内部维持三个相互咬合的回路，可以从任一处进入、并行、跳转和回退。

```text
认识回路：现实 → 观察 → 模型 → 预测或反例 → 修正

行动回路：目的 → 组织能力 → 实际授权 → 执行 → 状态与效果

建造回路：能力鸿沟 → 适配、组合或创造 → 真实验证 → 接入与复用
```

运行回路改变这次结果。建造回路改变系统以后能够做什么。

一次动作还要区分五种状态：模型提出、宿主或目标系统受理、实际执行完成、对象状态改变、预期效果出现。它们可能由不同系统在不同时间确认。命令成功不等于现实效果。

运行可以从人的表达、文件变化、工具结果、到期信号或另一个系统的请求进入。没有真实事件入口时，不假装系统在后台自行工作；用户回来时再核对变化。

## 演化：未来行为真的不同

系统是否演化，不看保存了多少内容，只看下一次是否因此不同。

低层反复失败时向上诊断：

```text
状态或偶然事件
→ 当前行动方式
→ 能力缺失或过时
→ 关系、反馈或权责设计错误
→ 更高层资源结构、边界或目标
```

高层改变再向下实现：

```text
新的目的、模型或结构
→ 改变能力要求
→ 改变组件、关系与权限
→ 改变行动
→ 观察新的状态与效果
```

新证据只更新真正受影响的认识、作品、能力和关系。用户修改与未受影响工作保留。依赖失效时，系统能指出哪些下游需要重审、哪些仍可使用、哪些目前未知。

## 自然语言、LLM、电脑与现实

| 部分 | 在系统中的作用 |
| --- | --- |
| **自然语言** | 表达目的、意义、模型、条件、例外、权利和质量，让人和 AI 可以共同阅读与修改。 |
| **LLM** | 解释当前处境，构造活动系统图，研究、推演、组织和创造。 |
| **代码与工具** | 承担精确、重复、可验证的观察、转换和执行。 |
| **AI 宿主** | 提供上下文、事件、权限、工具调用和结果回传。 |
| **领域系统** | 保有自己的权威状态、执行规则和内部自由。 |
| **现实结果** | 决定解释是否成立、行动是否生效、能力是否真正存在。 |

自然语言不是静态说明书，而是系统的可携带语义源。机器索引可以由它生成，不能反过来要求用户维护数据库。

## 组件怎样分工

| 组件 | 核心职责 |
| --- | --- |
| **共同内核** | 身份、主动性、体验承诺、系统定义、诚实、所有权和质量边界。 |
| **活动系统运行器** | 恢复当前系统、构造活动图景、选择尺度、组织工作、处理变化。 |
| **认识系统** | 观察、建模、检验与两岸认识。 |
| **能力组织器** | 直接完成、复用、组合、创造或交给人的分工判断。 |
| **关系系统** | 让差异和能力跨边界形成实际作用。 |
| **执行与效果层** | 宿主权限、电脑工具、外部行动、状态与效果确认。 |
| **作品与体验** | 把深层认识变成人能看见、使用和接手的成果。 |
| **演化层** | 结构上浮、依赖传播、能力沉淀、系统分化与组合。 |

第一轮不需要把所有组件永久保存。它们在需要时进入活动系统，真实产生长期价值后才成为用户系统的一部分。

## 作品：深层模型抵达人的地方

作品不是系统报告的包装。它是 AI 对对象的认识与人真正理解之间的桥。

完整作品要有一个对象专属、足以改变理解或行动的中心。产业可以长成一座能进入的世界，公司可以是一幅控制结构，代码库可以是一张执行剖面，反复工作可以直接长成工具。形式服从发现与用途。

交互只在它能让人比较、验证或看见动态时出现。复杂作品提供全景、当前位置和回到整体的入口。去掉所有控件和装饰后，核心发现仍应有力量。第一屏先让人看见真实发现，而不是项目说明。

系统事件简短出现，只说真正发生的变化：发现、接入、成果完成、能力验证、系统写回和回来。搜索、读文件与普通工具调用不变成表演进度。

## 用户拥有的系统

每个长期系统有一个自然语言入口 `SYSTEM.md`。它没有固定模板，但陌生的人或 AI 读完应知道：这是什么、为谁与为何存在、目前怎样理解、依据和未知、能做什么、重要作品与能力在哪里、连着什么、现在最值得做什么、怎样继续。

它不是聊天摘要、活动日志或关于人的零散记忆。保存的是会改变以后工作的系统状态：对象认识、人的实际理解、用户纠正、作品、已验证能力、重要关系、适用条件和下一次起点。

用户可以阅读、修改、带走和结束系统。个人、项目、领域和外部系统各自拥有自己的状态与边界。

## 开放系统世界

更高层系统不是中央系统吞并其他系统，而是独立系统围绕共同目的形成新的整体能力。

每个子系统保有：

- 所有权与权威状态
- 内部自由
- 授权边界
- 纠正和退出权

公共层只维护真实协作所需的关系、语义、来源、验证和反馈。一个系统的作品、认识、能力或子系统可以被另一方采用、适配和验证，实际反馈再回到能改进它的一方。

## 实现位置

[SKILL.md](../skills/open-x-sys.zh-CN/SKILL.md) 是完整的自然语言运行时入口。它保留身份、体验、系统观、主动性、作品标准、信任边界和足以独立开始工作的运行语义，不被缩成一张薄路由表。复杂现场再按需进入七层结构：

| 层 | 正式位置 | 责任 |
| --- | --- | --- |
| 共同内核 | [`core/`](../skills/open-x-sys.zh-CN/core/) | 宪法、系统、关系、能力与演化的不变量；认识论与系统科学作为深层资源。 |
| 系统运行时 | [`runtime/`](../skills/open-x-sys.zh-CN/runtime/) | 激活、恢复、组装、观察、行动、验证和更新；这些职责自由跳转、递归和并行。 |
| 系统实例 | [`system/`](../skills/open-x-sys.zh-CN/system/) | 实例、状态、所有权、组成与接续，以及自然语言入口的详细形态。 |
| 能力引擎 | [`engines/`](../skills/open-x-sys.zh-CN/engines/) | 理解、探索、表达、建造与演化。 |
| 能力资源 | [`capabilities/`](../skills/open-x-sys.zh-CN/capabilities/) | 方法、模式和高手路线；增强判断，不控制全局运行。 |
| 环境适配 | [`adapters/`](../skills/open-x-sys.zh-CN/adapters/) | 把宿主、文件、工具、Web、人和外部系统的真实边界接入运行。 |
| 人的体验 | [`experience/`](../skills/open-x-sys.zh-CN/experience/) | 声音、作品、系统事件、全景与返回；展示细节和试验场也在这里。 |

`agents/` 与 `assets/` 是 Skill 的宿主发现元数据和品牌资源，不属于运行语义层。七层不是七步：它们围绕同一个活动系统实例按需共同作用。

## 最终检验

OpenXSys 成功运行时，一个不了解系统思维的人只说一句普通的话，也能得到改变认识的发现、真正完成的作品或一种以前没有的能力。他不觉得自己在走流程或维护系统，却能随时掌控方向。

同类问题反复出现时，系统会修改生成问题的高层结构。缺少能力时，系统能组织或创造并在现实中验证。新会话、新模型和其他系统能够接续。多个系统可以组成更大的能力，也可以各自退出。

> **内部运行的是系统，用户经历的是自己的故事。**
