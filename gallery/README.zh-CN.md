## 把你的得意之作放到这里

一份产业研究、一个可探索的解释、一件作品，或你围绕真实问题搭建的能力，都可以成为下一个展示案例。

1. 把最终成果与预览图整理到 `gallery/YYYY-MM-DD-your-title/`。
2. 在目录的说明文件中写下：那一句提示词、使用的 AI 工具与模型、运行日期，以及成果的来源。
3. 在 GitHub 上传文件并提交 Pull Request，也可以先提交一条附作品链接的 Issue。可以参考 [GitHub 的上传文件说明](https://docs.github.com/en/repositories/working-with-files/managing-files/adding-a-file-to-a-repository)。

也可以把这段话交给你的 AI：

```text
请把这次使用 OpenXSys 做出的成果整理成作品集投稿。
保留最终成果、预览图、提示词、使用的 AI 工具与模型、运行日期和来源，
放入 gallery/ 下按日期与主题命名的目录，并准备一份 Pull Request 说明。
```

[完整贡献指南](../CONTRIBUTING.zh-CN.md)

## 一个条目包含什么

每个条目一个文件夹，在说明里写明日期与对象：

- 成果，翻译或展示整理在运行说明中写明；
- 它的分享包：1:1 与 9:16 的发现卡，做了的话还有短视频，文案草稿，替代文字；
- `README.md` / `README.zh-CN.md` 或 `ABOUT.md`：输入的那句话、走过的路线、模型与宿主、日期、已经记录的依赖和用时，以及这份成果所依据的来源；
- 指向 `playground/replays/` 里它的回放的链接（如果公开了的话）。

## 规矩

- 只收真实的运行，是挑选出来的，从不是编排出来的。
- 条目里的每个事实论断都有来源和日期。
- 去掉一切个人内容，并由运行者批准公开的内容。
- 条目带日期：它显示的是那一天、那个模型下系统做了什么。

怎样添加，见 [CONTRIBUTING.zh-CN.md](../CONTRIBUTING.zh-CN.md)。项目 README 里的精选成果，就来自这些实际运行。
