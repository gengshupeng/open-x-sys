## Put your best work here

An industry study, an explorable explanation, a finished creation or a capability built around a real problem can become the next showcase.

1. Put the final deliverable and a preview image in `gallery/YYYY-MM-DD-your-title/`.
2. Record the prompt, AI tool and model, run date and sources in the entry's notes.
3. Upload the files on GitHub and open a pull request, or start with an issue linking to your work. See [GitHub's file-upload guide](https://docs.github.com/en/repositories/working-with-files/managing-files/adding-a-file-to-a-repository).

You can also ask your AI:

```text
Prepare the work we made with OpenXSys for a gallery submission.
Include the final deliverable, a preview, the prompt, AI tool and model,
run date and sources. Put them in a dated subject folder under gallery/
and prepare a pull request description.
```

[Full contribution guide](../CONTRIBUTING.md)

## What an entry contains

One folder per entry, with the run date and subject in its notes:

- the deliverable, with any translation or showcase edits described in the run notes;
- its share pack: discovery cards in 1:1 and 9:16, the short clip if one was made, post drafts, alt text;
- `README.md` / `README.zh-CN.md` or `ABOUT.md`: the sentence typed, the route taken, the model and host, the date, dependencies and duration when recorded, and the sources the deliverable rests on;
- a link to its replay in `playground/replays/`, if published.

## Rules

- Real runs only, chosen and never scripted.
- Every factual claim in an entry has a source and a date.
- Anything personal is removed, and the person who ran it approves what is published.
- An entry is dated: it shows what the system did on that day with that model.

To add one, see [CONTRIBUTING.md](../CONTRIBUTING.md). Featured work in the project README comes from these actual runs.
